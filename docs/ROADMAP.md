# 演进路线（ROADMAP）

> forge-1024 · 内核 1.0.0 / 编目 2026.10
> 路线原则：**先纵深（把 1024 条做对做透），再横向（性能与生态）**。

---

## v1.0（当前 · 已交付）

- [x] 内核五件套：Tensor（NumPy 广播/归约语义）、PCG32 RNG、注册表、遥测、错误分类学
- [x] 10 域（6×102 + 4×103）= **1024 条**微指令，每域文件末尾编目自检
- [x] 不变量体系：解析↔数值、双路径一致、定理级性质、差分检验、结构不变量、概率公理
- [x] 零依赖：0 个 npm 包，Node ≥ 18 直接运行
- [x] 文档由注册表反射生成（`tools/gen-ops-doc.mjs` → `docs/OPS.md` / `docs/REFERENCES.md`）
- [x] 单文件 HTML 产物（Blob ESM 内联，浏览器内自检）
- [x] CI：3 OS × 3 Node 版本矩阵，编目自检 + 单元测试 + 示例冒烟 + 基准
- [x] 6 个可运行示例

## v1.1 · 纵深加固

- [ ] **不变量覆盖率 100%**：为每条指令补一条独立交叉验证测试，并把覆盖率做成可报告的指标（`sys.verify.invCoverage`）
- [ ] **属性测试（Property-based Testing）常态化**：把 `sys.verify.fuzz` 接入 CI，对 1024 条指令做 seed 化的批量模糊测试
- [ ] **数值边界清单**：为每条指令登记定义域与边界行为（空输入 / NaN / Inf / 非正定 / 秩亏），形成「边界契约表」
- [ ] **复数与高精度**：`num.dd*` double-double 家族扩展到关键分解（QR / Cholesky）的双精度加长版

## v1.2 · 性能

- [ ] **matmul 自适应分块**：按 L2/L3 缓存尺寸选择块大小，目标把 512×512 吞吐再提升一个量级
- [ ] **SIMD 友好布局**：探索 `Float64Array` 上的循环展开与寄存器分块
- [ ] **基准回归基线**：把 `bench/bench.mjs` 结果纳入 CI 作为性能回归门槛（相对阈值告警）
- [ ] **可选的 WebAssembly 后端**（保持默认路径零依赖，WASM 作为可选加速模块）

## v1.3 · 能力扩展

- [ ] **分布式/并行**：在 Node `worker_threads` 上做数据并行批处理（仍零依赖）
- [ ] **模型序列化格式**：基于 JSON 的 `.forge` 模型格式（参数 + 指纹 + 编目版本），支持跨版本加载校验
- [ ] **更多现代架构组件**：MoE 全量路由与负载均衡损失、Mamba/SSM 扫描、FlashAttention 分块 IO 复杂度实测
- [ ] **图优化**：`sys.graph.*` 增加常量折叠、公共子表达式消除、算子融合

## v2.0 · 生态

- [ ] **语言无关的内核描述**：把编目导出为机器可读的 ISA 描述（JSON Schema），供其它语言实现「同构内核」
- [ ] **教学套件**：按「数学基础 → 经典 ML → 深度学习」顺序的交互式 notebook（单文件 HTML）
- [ ] **交叉实现对照**：与 NumPy / SciPy / PyTorch 的结果对照脚本（可选依赖，仅用于对照，不进运行时）

---

## 非目标（明确不做）

- **不引入运行时依赖**：可选工具（如对照脚本）可以依赖三方库，但内核本身永远保持 0 依赖。
- **不追求 GPU**：GPU 需要驱动与编译链，违背「零构建、可长期保存」原则；性能目标限定在纯 JS 可达范围内做到极致。
- **不扩张指令总数**：1024 是硬上限。新增能力必须归入既有域并替换/合并一条现有指令，由 CI 强制。
- **不写与实现分离的文档**：所有文档要么由注册表反射生成，要么是对架构与设计原则的说明。
